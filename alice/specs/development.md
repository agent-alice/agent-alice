# Alice 开发与验收规范

本规范适用于 Alice 扩展源码、测试、安装产物和运行切换。它定义协作与验收要求，不表示当前已经配置远端 CI、必需检查或完成生产切换。

## 架构与数据边界

Codex CLI / App Server 提供模型循环、工具执行、原生线程、子代理和上下文压缩。Alice 通过公开接口管理持续状态、调度、来源档案和候选发布；不得通过修改或复制 Codex 核心实现集成。

本地服务当前使用 Unix sockets、fcntl 和进程组，范围为 macOS / Linux。平台限制必须明确说明，不能把单平台结果推广成全部平台支持。

Git 保存源代码、合成 fixtures 和通用文档。身份、私密 prompt、长期记忆、原始日志、凭据和本机部署状态留在仓库外。报告仅包含必要统计、hash 和脱敏证据；测试不能消费正式任务、生产记忆或真实发布渠道。外部发送、账户操作及真实模型费用遵循当前任务的明确授权。

## 任务、文件归属与交接

1. 开始前检查已有 issue 和 PR，明确问题、预期行为、范围、依赖和可观察的验收条件。
2. 每项可独立验收的任务使用自己的分支与 worktree，说明文件所有权；共享协议或模块先协调，不覆盖其他协作者的修改。
3. 在既有授权内推进。范围或依赖变化时更新任务说明，让结论围绕最终实现，不保留过时的完成状态。
4. PR 关联任务，列明改动后行为、实际证据、数据兼容和剩余限制；未完成集成时保持 Draft。
5. 交接说明可复现入口、确切版本、观察结果和待办；接收者需核对证据，不能仅转述“子代理说通过”。

## 测试分层

| 层级 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 单元／合成传输 | 状态、时间、异常和持久化规则 | 真实进程与协议连接 |
| 真实 Codex 二进制、受控响应 | 公开协议、MCP、线程和生命周期 | 真实模型的任务能力 |
| 干净环境安装产物 | 交付包的依赖、入口和实际运行 | 另一产物或开发环境的行为 |
| 经授权的真实模型评测 | 指定任务集中的结果与消耗 | 通用学习、自主能力或其他业务覆盖 |

针对改动运行必要的行为测试，优先覆盖实际故障、恢复路径和外部结果。不要只模拟内部实现来制造覆盖率；修改快照或预期值时，要证明新结果满足目标语义。先运行相关检查，只有新变化、失败或未解决风险才扩大或重复测试。

每份报告记录测试目标、源码 commit／候选 hash、依赖和 Codex 版本、完整命令、测试数量、退出状态及证据位置。passed、failed、skipped、not_run 分开列出。超时、空测试集、模型自述、健康接口返回成功和测试脚本存在都不能代替验收。不能让模型自填的 passed 字段授权发布，也不能将旧轮子的结果套给新构建。

从包含源码的目录可以运行：

```sh
python -m pytest tests -m 'not native and not live and not artifact' -q
ALICE_TEST_CODEX_BINARY="$ALICE_CODEX" \
  python -m pytest tests -m 'native and not live and not artifact' -q
python tools/check.py --source . --codex-binary "$ALICE_CODEX" --native \
  --report /path/to/private-check-report.json
```

`tools/check.py` 的 source、installed-artifact 和可选 native 门槛需确实收集并执行测试。没有显式真实二进制时不能宣称 native 通过。live 测试单独选择，要求明确授权、配置、预算和非空测试集；凭据不进入日志或产物。

## 必须覆盖的故障与恢复

| 场景 | 验收结果 |
|---|---|
| 配置损坏、MCP 初始化失败 | 保留原数据并明确失败，不自动重置为空环境 |
| 重复请求、重复事件、并发 claim | 稳定 ID 可对账，受控任务不因重试并发执行 |
| 原生打断、控制面暂停、进程退出 | 观察真实终态，暂停持久化，无迟到结果继续派发 |
| SIGKILL 与普通重启 | 恢复正确线程及任务关联，不新建重复主线程，不解除人工暂停 |
| 到期积压、时区和日历边界 | 覆盖约定的全部关闭窗口，无唤醒风暴或静默漏段 |
| 快照时来源变动、摘要写入中断 | 不提交半成品，不丢原始记录，引用与来源版本可回查 |
| 新旧工作区同时修改 | 返回冲突并保留两侧内容，不覆盖手记或新消息 |
| 失败候选、数据 schema 不兼容 | 阻止激活或不安全回退，保留稳定版本与数据 |
| 观察不完整、结果不明 | 明确缺失并独立对账，不能凭工具成功宣布业务完成 |

外部动作不具备由本地事务自动保证的 exactly-once。应使用外部幂等键或查询回执；结果不明时先对账，不能换 ID 盲重试。

## 安装产物、发布与自修改

开发和自修改在独立候选目录进行，活动服务使用固定产物。构建记录源码、依赖锁定、配置／数据版本和 Codex 二进制 hash。候选在隔离状态与合成资料上验证，不得与活动实例同时消费正式渠道。

发布顺序为：构建候选 → 验证同一产物 → 保留稳定版本和可恢复数据 → 暂停派发并对账 → 切换唯一入口 → 检查确切版本的行为。切换前不能临时重建成另一份未验收产物。必需检查失败、缺失、跳过、超时或源码变化应阻止激活；不要配置空成功 CI。

回退分别检查代码、配置及数据兼容性，不等于 git reset。格式、持久 ID 或路径变化必须显式迁移并留恢复依据；不可逆变化使用副本或新一代数据。回退保留切换后新增消息、经历、任务和外部回执，不把旧快照覆盖回当前数据，也不让两套运行器共享可写记忆。

发布检查、测试和预期结果本身发生变更时，必须明确评审，并证明错误候选仍会被拒绝。完整门槛和回退链路验收前，不启用无人值守的自修改部署。

## 学习与完成状态

规则、技能或摘要落盘只说明内容存在。学习结论需要失败证据、纠正、回归及未见变体上的实际结果；区分事实、假设、缺失与尚未验证的经验。评测应有可执行判定器，分别报告成功、失败、人工介入、耗时和资源消耗。

源码实现、组件测试、安装产物、部署恢复、原始资料完整保存、最终切换与真实学习是不同验收项。报告必须逐项说明实际状态；规范文档和单个通过的测试不能把其余项目标为完成。
